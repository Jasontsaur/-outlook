# Outlook 郵件整理規則

這份文件定義 Claude 判斷「一封信該分到哪一類 / 該搬到哪個資料夾」的依據。
規則寫得越具體，Claude 判斷越準、也越不用靠語意猜測（省 token、降低誤判）。

**目前整理範圍：近一年的郵件（其餘先不動）。**

## 1. 分類架構

```text
Projects/            工程專案（依專案分子資料夾）
├── <專案代號A>/
├── <專案代號B>/
└── ...
Customers/           客戶（依客戶分子資料夾）
├── <客戶A>/
└── ...
Vendors/             供應商（依供應商分子資料夾）
├── <供應商A>/
└── ...
Internal/            公司內部
Finance/              財務
Notifications/        通知（系統自動通知 / 電子報）
```

> 資料夾名稱可依你 Outlook 現有習慣調整，等 V0.2 的 `outlook_list_folders`
> 掃過現況後可以對照修正。

## 2. 分類規則

規則採「由上到下、符合就分類」的方式；同時符合多條時，取信心分數較高的一條。
`confidence` 是給 Claude 參考的信心分級：
- **0.9+**：規則命中即可直接分類（例如專案代號出現在主旨）
- **0.6–0.89**：需要 Claude 再讀一下內文/寄件人確認
- **< 0.6**：不分類，列入「待人工確認」清單

### 2.1 公司內部（Internal）

```yaml
規則:
  - 條件: 寄件者網域包含 "ruentex"
    分類: Internal
    confidence: 0.9
```

### 2.2 工程專案（Projects）

```yaml
規則:
  - 條件: Subject 或 Body 包含 "<待補：專案代號/名稱>"
    分類: Projects/<待補：專案資料夾>
    confidence: 0.9
  # 依此格式，每個專案加一條
```

> 待補：請提供目前進行中的專案名稱/代號清單，我幫你逐一補上規則。

### 2.3 客戶（Customers）

```yaml
規則:
  - 條件: 寄件者網域為 "<待補：客戶網域>" 或 Subject 包含 "<待補：客戶簡稱>"
    分類: Customers/<待補：客戶資料夾>
    confidence: 0.9
```

> 待補：主要往來客戶名稱/網域。

### 2.4 供應商（Vendors）

```yaml
規則:
  - 條件: 寄件者網域為 "<待補：供應商網域>" 或 Subject 包含 "<待補：供應商簡稱>"
    分類: Vendors/<待補：供應商資料夾>
    confidence: 0.9
```

> 待補：主要供應商名稱/網域。

### 2.5 財務（Finance）

```yaml
規則:
  - 條件: 寄件者為 "<待補：會計/請款系統寄件者>" 或 Subject 包含 "請款|發票|報帳|付款"
    分類: Finance
    confidence: 0.8
```

> 待補：財務類信件通常的寄件者（人或系統）。

### 2.6 通知（Notifications）

```yaml
規則:
  - 條件: 寄件者為系統自動信（例如 Teams、ERP、雲端硬碟、電子報退訂連結存在於內文）
    分類: Notifications
    confidence: 0.85
```

> 待補：具體會被視為「通知」的寄件者或關鍵字（例如是否包含行銷電子報）。

## 3. 未分類 / 低信心處理

不符合以上任何規則、或信心 < 0.6 的信件，**不會**自動搬動，而是列進候選清單
（`staging/*.csv`）讓你人工確認後，再由 Claude 執行搬移。

## 4. 使用方式

1. 你補上「待補」的具體名稱/關鍵字
2. Claude（透過 V0.2 起的 `outlook_search`）依規則掃過去年信件，先只**輸出統計報表**（各分類多少封），不搬動任何郵件
3. 你檢查報表覺得規則需要調整的地方
4. 規則穩定後，才開放 Preview + 實際搬移（V0.4）
